# 巨兽锻坊 v3：CrazyGames 版策划方案

> 状态：待确认后实施  
> 日期：2026-09-14  
> 目标平台：CrazyGames（桌面浏览器优先）  
> 引擎：Unity 2022.3.52f1  
> 原型范围：4 把武器、12 个 Boss  
> 完整范围：16 把武器、48 个 Boss

## 1. 项目目标

制作一款只需要鼠标点击或触屏点击的数值成长射击游戏。玩家用有限弹药攻击 Boss，命中便获得金币，弹量和火力决定本次挑战能否通关。金币用于强化当前武器、提高全局金币收益和解锁下一把武器。

游戏面向想在浏览器中快速获得数值反馈、每次游玩约 5～20 分钟、长期逐步解锁全部武器的玩家。关闭游戏后不产生离线收益，长期动力来自武器收藏、稳定成长、关卡推进和再次游玩时保留的进度。

设计必须同时解决两件事：

1. 玩家进入页面后几秒内就能理解并开始射击。
2. 卡关时每次点击仍然推进金币成长，不能再次出现数分钟没有购买或推进的真空期。

## 2. 已采用的假设

1. 玩家点击战斗区域一次，发射一颗子弹；不设置攻击冷却，也不支持按住连射。
2. 射击自动命中当前 Boss，不增加移动、准星或闪避操作。
3. 每把武器拥有独立的火力等级和弹量等级，换枪不会继承这两项等级；已经购买的等级永久保留。
4. 每次挑战自动补满当前武器的弹药，Boss 血量重新恢复。
5. 弹药归零后先等待所有在途子弹结算；Boss 仍存活才判定失败。
6. 挑战失败不会没收已经通过有效伤害获得的金币，也没有额外失败惩罚。
7. 金币强化为全局永久强化，每级线性增加 3 个百分点：`1 + 等级 × 0.03`。
8. 金币强化放大普通命中收益和普通击败奖励；首次通关额外奖励保持固定，不被放大。
9. 已通关 Boss 仍由玩家手动选择回刷，系统不自动选择、不排序、不标记“最佳收益”。
10. 不提供离线金币；关闭页面期间所有战斗和收益停止。
11. 首版不同武器的差异以数值、弹道、音效和反馈表现为主，不引入暴击、散射、穿透等额外规则。
12. CrazyGames 版至少支持英文和简体中文；无法取得平台语言时默认英文。

> 决策记录（2026-09-14）：已确认挑战失败时保留本次有效伤害产生的全部金币。

这些假设构成本版实现基线。若其中任何一项不符合预期，应在进入代码实施前修改本文。

## 3. 产品定位

### 3.1 核心卖点

- **每次点击都有收益：** 有效伤害立即转化为金币，失败也会变强。
- **火力变化清楚可见：** 强化后单发数字、目标受击和所需点击次数立即变化。
- **有限弹药形成目标：** 玩家清楚看到自己差几发通关，自然产生“再升一级”的动力。
- **16 把现代武器连续换代：** 从制式手枪成长到 M134 转管机枪，始终有下一件明确目标。
- **低操作门槛：** 点击即可射击，选择只发生在武器强化和手选回刷目标上。

### 3.2 公共版本的原创方向

公开视频《顶配枪手》只作为点击节奏、有限弹药和金币反馈参考。视觉语言改为参考 Bowmasters 一类夸张的 2D 漫画投射游戏：粗细不均的深色轮廓、扁平高饱和色块、纸片关节、夸张成人角色比例、幽默受击动作和明亮竞技场。

公开成品继续采用自己的名称、角色、武器造型、界面结构、数值、敌人、场景和音效。参考范围只限高层视觉特征，不直接使用 Bowmasters 或《顶配枪手》的角色、服装、界面、素材、关卡、名称或品牌标识。战斗保持无血腥的漫画受击反馈，以装甲震动、肢体后仰、星形闪光、伤害数字和金币弹出表现命中。

## 4. 核心游戏循环

```text
进入独立主菜单
    ↓
选择武器 / 强化火力与弹量 / 强化金币 / 选择 Boss
    ↓
点击“战斗”进入独立战斗界面
    ↓
点击战斗区域发射子弹
    ↓
子弹命中：扣除 Boss 生命并立即获得金币
    ↓
┌─ Boss 被击败 ─→ 领取击败奖励 → 解锁进度 → 结算 → 返回主菜单
│
└─ 弹药用尽 ───→ 等待在途子弹 → 挑战失败 → 保留命中金币 → 结算 → 返回主菜单
```

第一次和后续进入游戏都显示主菜单。新玩家默认选中第一把武器和第一关，主按钮突出显示“战斗”，从页面可操作到开始游戏只需要一次点击。首次进入战斗时显示一次“点击射击”提示，玩家第一次射击后提示消失。

## 5. 战斗规则

### 5.1 状态流程

| 状态 | 行为 | 可用输入 |
|---|---|---|
| 主菜单 | 显示角色、武器、强化、金币和 Boss 选择 | 开始、强化、换枪、选关、设置 |
| 战斗加载 | 锁定本局武器、火力、弹量、金币倍率和 Boss | 无 |
| 战斗 | 独立场景中点击战斗区域发射子弹 | 射击、暂停、退出 |
| 结算中 | 弹量为 0，但仍有子弹在途 | 无，等待最后命中 |
| 胜利 | 发放普通击败奖励和可能存在的固定首通奖励 | 返回主菜单 |
| 失败 | 保留命中金币，说明还差多少伤害 | 返回主菜单 |
| 全部通关 | 主菜单保留选关和回刷，可继续强化 | 选关、强化、战斗 |

### 5.2 一次射击

1. 只有点击战斗区域才射击；点击按钮、武器列表或 Boss 列表不会误触发。
2. 当剩余弹药大于 0 时，每个点击事件生成一颗子弹并立即扣除一发弹药。
3. 同一帧可以接受多次点击，不设置人为射速上限。
4. 进入战斗时锁定当前武器、火力、弹量和金币倍率；整场战斗都使用这份快照。
5. 战斗界面不提供任何升级、购买、换枪或选关入口；玩家必须结算并返回主菜单后才能改变成长配置。
6. 子弹经过短暂飞行动画后命中，伤害按战斗开始时锁定的火力计算。
7. Boss 被击败后，尚未命中的子弹失效，不再发放伤害或金币。

### 5.3 胜负判定

- `Boss 当前生命 <= 0`：立即进入胜利状态。
- `剩余弹药 = 0 且在途子弹 > 0`：进入结算中状态。
- `剩余弹药 = 0 且在途子弹 = 0 且 Boss 仍存活`：进入失败状态。
- 挑战没有倒计时，也不会因为玩家停止点击而失败。
- 重新挑战时弹药补满、Boss 血量恢复；本局已获得金币不会回滚。

### 5.4 点击负担目标

- 第一关预计 6～10 次点击通关。
- 普通关卡预计 8～18 次点击通关。
- 每组三关的第三关预计需要 15～25 次点击，或通过 1～2 次强化减少点击量。
- 常规关卡不超过 30 发基础弹量；特殊 Boss 上限暂定 40 发。
- 计划路线中，卡关后最多重复挑战 2 次便可以买到一个能改变结果的强化。

## 6. 经济与数值规则

### 6.1 结算结构

每个 Boss 的普通总收益分为两部分，原型初值采用：

- 有效伤害收益池：普通总收益的 70%。
- 击败奖励：普通总收益的 30%。
- 首次通关奖励：独立固定值，不受金币强化影响。

70/30 是首轮测试参数，不是最终比例。它的目的，是让失败尝试有明显进展，同时保留击败 Boss 的额外满足感。

### 6.2 有效伤害收益

金币按实际扣除的生命值结算，过量伤害不产生额外收益：

```text
有效伤害 = min(本发火力, 命中前剩余生命)
普通金币倍率 = 1 + 金币等级 × 0.03
```

为了避免不同单发火力产生取整差异，按 Boss 累计受伤比例计算金币增量：

```text
本发金币 = floor(强化后伤害收益池 × 命中后累计伤害 / Boss总生命)
         - floor(强化后伤害收益池 × 命中前累计伤害 / Boss总生命)
```

这保证完整击败同一个 Boss 时，伤害部分的金币总量固定，不会出现弱枪因为打得更久而赚得更多，也不会通过过量伤害刷金币。

### 6.3 金币强化

```text
金币倍率 = 1 + 0.03 × 金币强化等级
```

示例：

| 等级 | 普通金币倍率 |
|---:|---:|
| 0 | 1.00 |
| 1 | 1.03 |
| 5 | 1.15 |
| 10 | 1.30 |
| 20 | 1.60 |

金币强化不采用复利。价格应按照预计回本时间校准，首轮目标为 15～25 次同阶段完整击败后回本。若它长期抢占换枪资金却感受不到收益，应降低价格，而不是提高倍率。

### 6.4 单把武器强化

每把武器有两条永久强化：

| 强化 | 原型初值 | 玩家感受 |
|---|---|---|
| 火力 | 每级增加该武器基础火力的 8% | 每发伤害提高，击败所需点击减少 |
| 弹量 | 每级增加 1 发 | 总伤害上限提高，可以跨过卡关门槛 |

计算采用基础值线性增长：

```text
当前火力 = round(基础火力 × (1 + 0.08 × 火力等级))
当前弹量 = 基础弹量 + 弹量等级
```

首轮每把武器暂定火力 8 级、弹量 8 级。实际等级上限由 4 把枪、12 关测试决定。界面必须显示升级前后变化，例如“97 → 105”或“16 → 17”。

### 6.5 新武器

- 武器按固定顺序使用金币解锁，价格严格递增。
- 新武器解锁后自动装备，玩家可以随时切回已经拥有的武器。
- 新武器的基础火力和弹量不得低于它负责关卡段的最低通关需求。
- 换枪后，回刷当前常用目标所需点击数应立即下降约 35%～50%。
- 旧武器的强化永久保留，可用于玩家自行判断回刷收益。

完整武器顺序沿用当前 16 把现代远程武器：

1. 制式手枪
2. 重型手枪
3. 冲锋手枪
4. MP5 冲锋枪
5. P90
6. 战术霰弹枪
7. 卡宾枪
8. 突击步枪
9. HK416
10. SCAR-H
11. 精确射手步枪
12. 栓动狙击步枪
13. 重型狙击步枪
14. 轻机枪
15. 通用机枪
16. M134 转管机枪

公开版本可在不改变数值职责的前提下调整通用名称，避免不必要的商标或外观授权问题。

## 7. 关卡结构

16 把武器分别对应一个三关段，共 48 个 Boss：

| 关卡位置 | 作用 | 初始弹量消耗目标 |
|---|---|---:|
| 第 1 关 | 展示新武器的碾压感 | 40%～55% |
| 第 2 关 | 稳定成长 | 65%～80% |
| 第 3 关 | 制造一次明确强化需求 | 95%～115% |

第三关可以略高于新枪基础总火力，迫使玩家购买火力或弹量；但通过一次失败收益和最多两次回刷，必须能够买到有效强化。击败第三关后，下一把武器进入可购买状态。

Boss 的变化重点放在反馈层：装甲阶段、零件破坏、体型、场景和受击动画。v3 原型不增加防御类型、元素克制或随机闪避，确保结果只由武器数值和点击数量决定。

## 8. 成长节奏验收线

以下为内部数值目标，不是 CrazyGames 保证通过的门槛：

| 节点 | 目标时间或体验 |
|---|---|
| 首次可操作 | 页面进入后 3 秒内，最多 1 次点击 |
| 第一关通关 | 10～20 秒 |
| 第一次强化 | 30 秒内 |
| 第二把武器 | 约 30～45 秒 |
| 第 4～5 把武器 | 5 分钟内 |
| 第一次明显卡关 | 玩家已经理解失败收益和强化关系之后 |
| 前 10 分钟 | 持续出现换枪、强化和新 Boss 外观，不连续重复同一目标超过 2 次 |
| 完整 16 枪、48 关 | 累计在线约 3～5 小时 |

全流程还必须满足：

- 以每秒 4 次点击、结算切换 1 秒的模拟路线计算，任何两次有效成长之间不超过 60 秒。
- 任何首次卡关到获得有效强化之间不超过 2 次失败挑战或 60 次有效点击。
- 每次换枪至少让当前常用目标的点击次数下降 35%。
- 价格表中所有武器解锁费用严格递增，不允许再次出现后一把比前一把便宜。
- 玩家选择不同回刷 Boss 时都能继续成长，不能出现金币死锁或数值溢出。

## 9. Boss 回刷

- 玩家可以从已通关列表中选择任意 Boss。
- 列表显示 Boss 名称、普通总收益、当前武器预计需要的子弹数和上次结算结果。
- 不显示每秒收益排名，不自动滚动到最佳目标，也不代替玩家选择。
- 切换目标后需要玩家点击开始，战斗不会后台自动运行。
- 首次通关奖励只发放一次，回刷只获得伤害收益和普通击败奖励。

“预计需要的子弹数”只做透明信息：

```text
预计子弹 = ceil(Boss 生命 / 当前火力)
```

它帮助玩家判断是否能通关，不直接告诉玩家应该回刷哪一关。

## 10. 界面与体验

### 10.1 桌面横屏布局

主菜单和战斗使用两个独立界面，共享同一套夸张 2D 漫画视觉语言。

主菜单包含：

- 左侧：当前原创枪手的全身形象。
- 中央：当前武器、火力、弹量以及对应升级按钮。
- 次级强化区：全局金币加成和升级按钮。
- 右侧：当前 Boss 肖像、关卡切换、基础奖励和首通状态。
- 底部：16 把武器横向列表以及醒目的“战斗”按钮。
- 顶部：金币、设置和游戏标识。

战斗界面包含：

- 主区域：左侧枪手、右侧大比例 Boss、弹道和命中反馈。
- 顶部：Boss 名称与生命、当前金币。
- 左侧边缘：剩余弹药。
- 角落：暂停和退出。
- 首次战斗底部显示一次“点击射击”提示。

战斗界面不得显示火力升级、弹量升级、金币升级、武器列表、Boss 列表、价格或商店入口。

测试重置放进设置面板，继续采用二次确认。主要战斗界面不显示调试信息。

### 10.2 美术语言

- 角色使用夸张成人比例、纸片式关节和清晰剪影；避免幼儿向圆润 3D 玩具感。
- 轮廓线粗细不均，形状略带手绘歪斜，搭配扁平色块、少量纹理和硬边阴影。
- 武器保留现代枪械类别的辨识度，同时简化零件、放大关键轮廓并使用非写实比例。
- 场景采用明亮城市屋顶、街区、港口等横向竞技场，每组三关共享一个地点主题。
- Boss 以原创夸张人物或非人目标呈现，不照搬参考游戏角色；最终人物世界观仍以用户对概念图的反馈确定。

### 10.3 关键反馈

每次射击至少出现：枪口闪光、子弹或曳光、Boss 受击、伤害数字、金币飞向金币栏、剩余弹药减少以及轻微音效。火力强化后增大伤害数字和受击强度；弹量强化后增加可见弹药格。

结算界面重点说明结果：

- 胜利：“击败奖励 +X，首次通关 +Y”。
- 失败：“还差 X 伤害；本局已保留 Y 金币”。
- 可购买强化时，对应按钮产生一次轻量提示，不自动购买。

### 10.4 本地化

所有玩家可见文本从集中式文本表读取，不在视图脚本中散落中文字符串。最低支持：

- 英文：平台默认和完整 QA 版本。
- 简体中文：当前开发与本地试玩。

数字缩写采用语言无关的 K、M、B、T 等单位；完整数值仍保存在整数类型中。

## 11. CrazyGames 发布约束

### 11.1 Basic Launch

- SDK 可选，但本项目计划提前接入游戏状态和存档接口，避免正式上线时重做。
- 广告完全关闭；界面中不能出现点击后无效果的广告按钮。
- 首次下载必须不超过 50 MB，项目内部目标为 20 MB 内。
- 压缩构建使用 Brotli 或 Gzip。
- Chrome、Edge 必须通过；Safari 无法稳定运行时可以在投稿配置中禁用。
- 桌面横屏必须可用，并在 821×462、907×510、1216×684、1280×720 等窗口检查可读性。
- 页面直接进入玩法，最多允许一次点击开始。

Basic Launch 重点关注平均游玩时长、次日留存和进入游戏后持续玩满一分钟的转化。官方示例中，表现较好的游戏常见平均游玩 10 分钟以上、次日留存 10%～15%、一分钟转化 80% 以上；这些用于内部观察，不作为保证通过的承诺。

### 11.2 Full Launch

- 接入最新 CrazyGames Unity SDK。
- 在玩家进入可玩状态时发送 Gameplay Start；打开设置、显示广告等暂停期间发送对应 Stop，恢复时重新 Start。
- CrazyGames 版本统一使用 Data 模块保存，登录用户跨设备同步，游客使用平台的本地存储。
- 只使用 CrazyGames SDK 提供的广告；广告被拦截、未填充或请求失败时，游戏必须恢复正常状态。
- 视频广告期间暂停战斗输入和游戏音频。
- 不在射击途中插入广告。

首个商业化候选仅保留两种：

1. 胜利结算时偶尔提供一次可选的双倍普通奖励。
2. 若以后需要插屏，只在数个关卡后的自然返回强化页请求。

任何关卡都必须能够通过正常升级完成，不以观看广告作为通关条件。

### 11.3 投稿素材

- 横版封面：1920×1080。
- 竖版封面：800×1200。
- 方形封面：800×800。
- 横、竖预览视频：各 15～20 秒、无声、50 MB 内；首帧使用对应静态封面。
- 英文游戏名、短描述、长描述和操作说明。
- 全部字体、音效、图形和其他素材的来源与商用许可记录。

封面只放游戏标题，不放“Play Now”、商店图标或平台图标。公共名称在制作正式封面前确定。

## 12. 存档方案

v3 使用独立的 schema 3，不覆盖现有 v2 试玩存档。最低字段：

```text
schemaVersion
coins
equippedWeaponIndex
unlockedWeaponIndex
weaponFirepowerLevels[16]
weaponAmmoLevels[16]
goldLevel
highestClearedBossIndex
lastSelectedBossIndex
firstClearFlags[48]
lastAttemptResults[48]
language
```

保存触发点：购买成功、命中金币结算、胜利、失败、切换武器、切换关卡和应用退出。连续命中期间可以在内存中即时更新，并按约 1 秒合并保存，减少 WebGL 存储调用。

后端按平台切换：

- Unity 编辑器和 Windows 测试：本地 JSON 文件。
- 普通 WebGL 开发构建：浏览器本地存储。
- CrazyGames 构建：SDK Data 模块，JSON 作为单个版本化字符串保存。

重置只清除当前 v3 存档；v1、v2 存档保留。

不为不同武器建立 16 套战斗类。首版所有武器共用一次射击规则，通过配置和表现参数区分。

### 13.3 代码约定示例

```csharp
public bool TryFire()
{
    if (Phase != BattlePhase.Fighting || RemainingAmmo <= 0)
        return false;

    RemainingAmmo--;
    pendingShots.Enqueue(new Shot(CurrentFirepower));
    return true;
}
```

- 状态修改集中在 `GameSession`，`GameView` 不直接计算伤害或发金币。
- 金额继续使用 `long`，生命和伤害使用 `double`，倍率结算使用 `decimal`。
- 玩家可见数值先计算再显示，界面文本不是规则来源。
- 固定价格和 Boss 表由校准工具生成，运行时不动态改价。
- 不添加与当前玩法无关的运行时依赖或通用框架。

## 14. 数值验证方法

离线模拟不再用旧版 DPS，而以点击和尝试为核心：

```text
模拟输入：每秒 4 次点击
每场切换：1 秒
购买策略：参考路线 / 优先换枪 / 优先火力 / 优先弹量 / 优先金币
```

每条路线记录：

- 每关首次挑战的子弹消耗和结果。
- 每次失败获得的金币及距离下一次有效购买的差额。
- 每把武器的解锁时间。
- 两次有效成长之间的最长秒数和点击数。
- 火力、弹量和金币强化的购买次数与回本时间。
- 完成 12 关和 48 关的时间。
- `long`、`double` 和 `decimal` 的边界与溢出情况。

原型先校准 4 把枪和 12 关。只有全部验收线通过，才按相同结构扩展剩余 12 把枪和 36 关。

## 15. 测试策略

### 15.1 编辑模式测试

必须覆盖：

- 一次点击只扣一发弹药并生成一颗子弹。
- 同一帧连续点击均可成功，没有攻击间隔。
- 点击 UI 不调用射击逻辑。
- 弹量归零后等待在途子弹再判定失败。
- Boss 死亡后取消剩余在途子弹及其收益。
- 失败保留有效伤害金币；返回主菜单后再次开战会补满弹药并恢复 Boss 生命，目标仍是失败的 Boss。
- 有效伤害金币总额不受单发大小和过量伤害影响。
- 金币倍率严格等于 `1 + 等级 × 0.03`。
- 固定首通奖励不受金币强化影响且只发一次。
- 每把武器的火力和弹量等级互相独立。
- 武器解锁价格严格递增。
- 玩家手选回刷目标，系统不代选。
- v3 保存、恢复、备份和重置不覆盖旧存档。
- 4 枪 12 关及最终 16 枪 48 关模拟无死锁并满足成长间隔。

### 15.2 浏览器检查

- Chrome 和 Edge 完整游玩一轮。
- 821×462、907×510、1280×720 和 1920×1080 无遮挡或不可点击区域。
- 页面刷新和浏览器重开后恢复正确进度。
- 快速连点不会丢失输入、重复结算或导致负弹药。
- 切换标签页回来后音频、时间和输入状态正确。
- SDK 不可用、广告被拦截或存档请求失败时仍可继续游戏。
- 发布构建压缩正确，首屏下载目标不超过 20 MB。

## 19. 完成标准

策划实施完成需同时满足：

1. 玩家使用鼠标或触屏完成全部操作，一次点击对应一颗子弹。
2. 没有战斗倒计时或攻击间隔；弹量和火力构成明确的通关门槛。
3. 主菜单和战斗界面完全分离，战斗期间没有升级、购买、换枪或选关入口。
4. 失败保留伤害收益，任何可达状态都能继续积累并购买有效强化。
5. 每把武器独立保存火力和弹量，全局金币强化每级线性增加 3%。
6. 16 把武器和 48 关的价格、生命、奖励全部固定并通过模拟报告。
7. 玩家继续手选回刷目标，系统不自动推荐。
8. 英文和简体中文完整可用，Windows 与 WebGL 存档行为经过验证。
9. CrazyGames Basic Launch 构建满足包体、压缩、分辨率、操作、原创性和 PEGI 12 要求。
10. Chrome、Edge 中运行稳定，刷新和重开不会丢失进度。
11. 形成可提交的三种封面、横竖预览视频、英文元数据和素材授权清单。
